# AGENTS.md — Survey Contour Generator (Flutter)

Flutter port of the single-file React web app `contour-v12_4-tin-fixed.html` (the **reference**;
never edit it). Targets: **Android, Web (offline-capable PWA), Windows**. Code must be
platform-agnostic; platform differences live only behind small interfaces.

## Non-negotiable product rules
- **UI is as-is.** Customers know the existing UI. Match layout, spacing, radii, colours, gradients,
  glow, fonts (Outfit for UI text, JetBrains Mono for numbers/inputs), copy text, emoji/glyph icons
  (e.g. `≡ Data`, `⚙ Settings`, `✎ Draw`, `◔ Analysis`, `☰ Layers`) and behaviour of the reference.
  The responsive breakpoint is 768px (sidebar becomes an overlay drawer below it, as in the CSS).
- **No new features, screens, buttons or menu items.** Removed on purpose (do NOT port):
  the CDN boot/progress screen (replaced by a plain logo + "ContourGen" splash only if needed),
  the "Make Offline" button/modal/badge and every "Offline/Online version" text.
- Keep the reference's quirks unless listed here. Known intentional fix: a coordinate/RL value of
  exactly `0` must NOT be dropped on import (the JS used `a || b` fallbacks).

## Architecture (feature-first Clean Architecture)
```
lib/main.dart                       bootstrap only (edge-to-edge, providers, runApp)
lib/src/app.dart                    MaterialApp + theme
lib/src/core/
  constants/  theme/  utils/  widgets/
  platform/   ports (interfaces) + conditional-import adapters (io / web)
lib/src/features/contour/
  domain/     entities/, services/ — PURE DART. No package:flutter, material_ui, dart:ui, dart:html,
              dart:io, or plugins. Enforced by test/architecture/domain_isolation_test.dart.
  data/       spreadsheet codec, compute runner, repositories
  presentation/ controllers/ (ChangeNotifier), screens/, widgets/, dialogs/, painters/
```
- Domain is already done and parity-tested against the JS (`test/fixtures/parity.json`,
  generated by `node tool/gen_parity_fixtures.js contour-v12_4-tin-fixed.html test/fixtures/parity.json`).
  Do not change domain algorithm behaviour; if you must touch it, the parity tests must still pass.
- UI imports: use `package:material_ui/material_ui.dart` (this SDK's Material package), not
  `package:flutter/material.dart`.
- State: `ChangeNotifier` + `provider`. Narrow rebuilds (`context.select`, `Selector`, `Consumer`).
  No business logic in widgets.
- Platform specifics via conditional imports (`if (dart.library.js_interop) ... if (dart.library.io)`),
  never `Platform.isX` checks scattered in UI. Web cannot use isolates: heavy work runs through a
  `ComputeRunner` (isolate on native, inline with UI yields on web).
- Rendering: `CustomPainter` for map, TIN visualizer and charts (no chart packages).

## Code quality
- `flutter analyze` must report 0 issues (strict-casts/inference/raw-types are on).
- Cyclomatic complexity ≤ 10, cognitive ≤ 15 per method; extract helpers.
- Dispose every controller/FocusNode/subscription/`ui.Image`/`ui.Picture`.
- No `print`; use `AppLogger` (`lib/src/core/utils/app_logger.dart`, kDebugMode-guarded).
- Validate inputs (numeric ranges, clamp lengths); sanitize labels in CAD exports (already done).
- Dependencies: only actively maintained Dart 3 packages. Approved: `provider`, `excel`,
  `file_picker`, `printing`, `pdf` (print page wrapper), `web` (for web adapters). Ask the orchestrator before adding others.

## Security / release rules
- Android: compile/target SDK 37 (Android 17), minSdk 24, `allowBackup=false`, network security config with no
  cleartext, edge-to-edge, release signed only from git-ignored `android/key.properties`
  (never debug-signed). Strip plugin-injected permissions (e.g. INTERNET) in the release manifest.
- Never commit secrets, keystores, `local.properties`, machine paths, device screenshots or logs.
- Do not take device screenshots or inject input on the user's phone.
